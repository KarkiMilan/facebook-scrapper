# Facebook GraphQL Scraper (Playwright + TypeScript)

It collects posts (text, reactions, comments, shares, video views) from any
public Facebook profile or page **without logging in**, by capturing the
initial GraphQL request parameters with Playwright, then paginating
`https://www.facebook.com/api/graphql/` directly with a lightweight HTTP/1.1
client — the same trick the original Python version used with `requests`.

Verified in practice: **277 posts across the last 10 days** scraped from a
busy page anonymously.

> **Note:** Scraping Facebook may violate its Terms of Service. Use only for
> personal/research purposes with accounts you own or content that is public.

## Why this approach works

| Attempt | Result |
| --- | --- |
| Plain `fetch` (undici, HTTP/2) | HTTP 200, but an **empty body** |
| HTTP/1.1 + browser User-Agent | HTTP **400** |
| HTTP/1.1 + full GraphQL variables, missing `__relay_internal__pv__` keys | `{"errors":[{"message":"A server error missing_required_variable_value..."}` |
| **HTTP/1.1 + full variables + a plain client UA (`python-requests/2.31.0`)** | **HTTP 200, ~460 KB of real post data** |

Facebook's web UI shows anonymous visitors a login wall (`"See more on Facebook"`)
after the first few posts — but the underlying GraphQL API happily serves the
whole timeline to a plain HTTP client. The scraper uses the browser only to
**discover** the request parameters (`doc_id`, feed `id`, initial `cursor`)
from Facebook's own network traffic, then drives the API directly.

## Directory structure

```
facebook-graphql-scraper-playwright/
├── src/
│   ├── cli.ts        # CLI entry point: parses args, runs the scraper, writes JSON
│   ├── scraper.ts    # Core FacebookGraphqlScraper class (orchestration, flows)
│   ├── browser.ts    # BrowserManager: launch/close, goto, scroll helpers,
│   │                 #   login popup dismissal, login-wall detection, login()
│   ├── http.ts       # postForm(): plain HTTP/1.1 POST + gzip/deflate/br decoding
│   ├── payload.ts    # buildTimelineVariables() (full GraphQL variables incl.
│   │                 #   __relay_internal__pv__ keys), buildPayloadForm(),
│   │                 #   parseGraphqlFormPayload()
│   ├── parser.ts     # ResponseParser: parses newline-separated GraphQL JSON
│   │                 #   lines, collects posts/feedback/context/creation time
│   ├── utils.ts      # Recursive finders (feedback, message text, creation time,
│   │                 #   owning profile, page info), time helpers, sleep()
│   ├── types.ts      # Shared TypeScript types (FeedbackNode, FormattedPost,
│   │                 #   ScrapeResult, InitPayload, ...)
│   └── example.ts    # Minimal programmatic usage example
├── tests/
│   ├── parser.test.ts             # Unit tests for ResponseParser
│   ├── utils.test.ts              # Unit tests for finder/time utils
│   └── fixtures/
│       ├── sample_graphql_response.json   # Old-format GraphQL response fixture
│       └── new_format_response.json       # Current-format GraphQL response fixture
├── .github/workflows/
│   ├── ci.yml       # GitHub Actions: typecheck + unit tests
│   └── scrape.yml   # GitHub Actions: manual anonymous scrape job (cached browsers)
├── .gitlab-ci.yml   # GitLab CI: typecheck/test + manual anonymous scrape job
├── package.json     # Scripts, deps (playwright, typescript)
├── tsconfig.json    # NodeNext, ESM, .ts imports, erasable-only syntax
└── <target>_posts.json   # Output generated by a scrape run (gitignored)
```

### What each `src/` file does

| File | Responsibility |
| --- | --- |
| `cli.ts` | Argument parsing, help text, output file writing, exit codes |
| `scraper.ts` | The orchestrator: warm-up, init-payload capture, **apiFlow** (no-login) + **scrollFlow** (logged-in/fallback), progress checks, formatting |
| `browser.ts` | All Playwright page work: headless/headed launch, scrolls, clicking the "Not now" login popup, `isLoginWalled()`, account login |
| `http.ts` | The GraphQL API client: form-encoded POST over HTTP/1.1 (the fix that makes it work) |
| `payload.ts` | Builds the exact `variables` string Facebook's web client sends (must include `__relay_internal__pv__` entries) |
| `parser.ts` | Splits the response into JSON lines and extracts posts/reactions/context/timestamps via utils |
| `utils.ts` | Version-tolerant recursive field finders (old + new FB response formats) |
| `types.ts` | Interfaces for every object flowing through the scraper |

> All modules import each other with `.ts` extensions and run **natively on
> Node ≥ 23.6** — there is no build step.

## How the scraper flows

```
CLI (cli.ts)
  └─ FacebookGraphqlScraper (scraper.ts)
       ├─ BrowserManager.launch()                    browser.ts
       ├─ warm-up visit to facebook.com              (sets base cookies)
       ├─ goto /<target>?locale=en_US
       │
       ├─ [no login]                                ─────────────────────
       │   ├─ dismiss login popup (2x)
       │   ├─ scroll to trigger the initial feed request
       │   ├─ wait for init payload capture          getInitPayload()
       │   │    └─ doc_id + id + cursor from Facebook's own request
       │   ├─ apiFlow()                             ★ preferred path
       │   │    └─ loop (max 5000 rounds):
       │   │         postForm(GRAPHQL_URL, buildPayloadForm(...))   http.ts
       │   │         parseBody() → collect posts, reactions, context
       │   │         advance cursor = page_info.end_cursor
       │   │         before_time = latest creation_time
       │   │         stop when beyond --days or has_next_page=false
       │   └─ scrollFlow()  (only if apiFlow fails/refuses)
       │
       └─ [logged in: --fb-account/--fb-pwd or --storage-state]
            └─ scrollFlow() → scroll + intercept GraphQL responses
                 └─ checkProgress() every 5 scrolls (wall detection,
                      stall detection, day-limit check)
                 └─ collect posts from captured responses

formatData() → dedupe by post_id → JSON output
```

The `apiFlow` is the workhorse: one round fetches ~3 posts in ~0.3 s, and each
round moves further back in time. The progress line (`9 more days of posts to
collect…`) comes from `compareTimestamp()` in `utils.ts` comparing the newest
post of each batch against the `--days` limit.

## Local setup

Requirements: **Node.js ≥ 23.6** and npm installed on your machine
(check with `node -v` / `npm -v`).

```bash
# 1. Install project dependencies locally
npm ci            # exact versions from package-lock.json
#     ...or, if you prefer a fresh install without a lockfile:
npm install

# 2. Download the Playwright chromium browser (one-time, ~150 MB)
npm run install:chromium

# 3. Verify the project is healthy
npm run typecheck
npm test
```

That's it — no `chromedriver`, no Python, no environment setup.

## Usage

```bash
npm run scrape -- <username_or_user_id> [options]
# or directly:
node src/cli.ts <username_or_user_id> [options]
```

### CLI options

| Option | Description | Default |
| --- | --- | --- |
| `-t, --target <id>` | Facebook user / page ID *or* username (required) | — |
| `-d, --days <n>` | How many days of posts to scrape | `61` |
| `-o, --output <file>` | Output JSON file | `<target>_posts.json` |
| `--open-browser` | Show the browser window (slower, good for debugging) | headless |
| `--no-progress` | Disable progress messages | progress on |
| `--fb-account <email>` | Login with this account | anonymous |
| `--fb-pwd <password>` | Password for `--fb-account` | — |
| `--browser <kind>` | `chromium` \| `firefox` \| `webkit` | `chromium` |
| `--storage-state <f>` | Use a saved Playwright session (logged-in cookies) | — |
| `--locale <code>` | Facebook UI locale | `en_US` |
| `--debug` | Per-round diagnostics (API status, body line counts, cursors) | off |
| `--user-data-dir <d>` | Persistent profile dir (cookies accumulate across runs) | — |
| `--no-warm-up` | Skip the `facebook.com` pre-visit | warm-up on |
| `-h, --help` | Show help | — |

### Quick examples

```bash
# Scrape a username for the last 10 days
node src/cli.ts officialroutineofnepalbanda --days 10

# Scrape by numeric page ID into a custom file
node src/cli.ts id --days 20 --output posts.json

# See the browser + debug diagnostics
node src/cli.ts some_user --days 30 --open-browser --debug

# Quiet run, no progress spam
node src/cli.ts some_user --days 7 --no-progress
```

### Scraping with a logged-in session

Anonymous mode usually suffices (the API path bypasses the login wall), but
for heavily restricted profiles you can:

```bash
# Option A — provide account credentials at runtime
node src/cli.ts some_user --fb-account you@example.com --fb-pwd 'your-password'
# NOTE: credentials are visible in process lists; prefer option B.

# Option B — reuse a saved session (no credentials in CLI)
# 1. Run a one-off headed session to create the profile:
node src/cli.ts some_user --open-browser --user-data-dir .fb-session
# 2. (log in manually in the browser window that opens)
# 3. Reuse the profile on later runs:
node src/cli.ts some_user --user-data-dir .fb-session
```

`--user-data-dir` accumulates cookies across runs, which also helps anonymous
scraping become more reliable over time.

## CI / CD

Both pipelines run the **typecheck + unit tests**, and provide a
**manual-only anonymous scrape job** (no cron — every run is at the click of a
button), with Playwright browsers cached so scheduled-style repetition doesn't
re-download ~150 MB each time.

### GitHub Actions

| File | Purpose |
| --- | --- |
| `.github/workflows/ci.yml` | On every push/PR: `npm run typecheck` + `npm test` |
| `.github/workflows/scrape.yml` | **Manual** (`workflow_dispatch`): pick `target` / `days` / `output`, scrapes headless anonymously, uploads the JSON artifact. Chromium cached in `~/.cache/ms-playwright` (keyed on `package-lock.json`) |

Trigger: **Actions → "Scrape (anonymous)" → Run workflow** → fill inputs → Run.

### GitLab CI

| Job | Purpose |
| --- | --- |
| `typecheck-and-test` | Every pipeline: typecheck + unit tests |
| `anonymous-scrape` | **Manual** (`when: manual`, web pipelines only): scrapes `$SCRAPE_TARGET` / `$SCRAPE_DAYS` variables, stores `scrape_output.json` as a 30-day artifact. Browsers cached under `.cache/ms-playwright` (`PLAYWRIGHT_BROWSERS_PATH`) |

Trigger: **CI/CD → Pipelines → Run pipeline** → select the `anonymous-scrape`
job → Play. Override target/days via project CI/CD variables.

## Testing

Unit tests run with Node's built-in test runner — no extra framework:

```bash
npm test          # node --test tests/parser.test.ts tests/utils.test.ts
npm run typecheck # tsc --noEmit
```

Fixtures under `tests/fixtures/` cover both the **old** and the **new**
Facebook GraphQL response shapes, so `utils.ts`'s recursive finders are
verified against each format.
